# 立项：对话历史留存与脱敏策略

> 状态：已实施（代码默认生效）。
> 关联审计项：隐私 #19「对话历史落库无脱敏策略」。

## 1. 现状与风险

`hub_user_conversations.payload` 存的是前端整包对话 JSON（`{activeId, conversations[]}`），
`save_user_conversations()` 直接 `json.dumps` 后覆盖写入。由此带来三个问题：

1. **无留存上限**：只要用户不停用，历史一直涨，单行上限 4.5MB、最多 40 会话只是体量护栏，
   不是时间护栏 —— 三年前的对话仍然在库。
2. **PII 明文**：用户可能在提问里贴邮箱、手机号、身份证号（例如"帮我写邮件给 a@b.com"），
   这些原样落库，一旦库被拖走或只读账号泄露，就是明文个人信息。
3. **不可自助清除**：用户在前端删除会话，只是新 payload 覆盖旧 payload，历史版本不可追溯，
   但"是否真的删掉了"没有审计证据。

## 2. 策略（三条，全部可开关）

| 策略 | 默认值 | 开关 | 说明 |
|---|---|---|---|
| 留存期 | 180 天 | `HUB_HISTORY_RETENTION_DAYS` | 超期会话在**落库前**被丢弃；`0` = 不限制 |
| 落库脱敏 | 开 | `HUB_HISTORY_MASK_PII` | 邮箱 / 手机号 / 身份证 / 长卡号确定性替换 |
| 体量上限 | 40 会话 / 4.5MB | 代码常量 | 原有护栏，保留 |

脱敏示例：

| 原文 | 落库后 |
|---|---|
| `a.user@example.com` | `a***@example.com` |
| `13812345678` | `138****5678` |
| `110101199001011234` | `110101********1234` |

**刻意不做的事**：不脱敏基因符号、坐标、PMID、DOI —— 这些是业务数据，
误伤会让历史记录失去价值。规则只匹配强 PII 形态，宁可少脱敏也不猜。

## 3. 实现位置

- `core/privacy.py`
  - `mask_text` / `mask_obj` / `mask_payload`：递归确定性脱敏；
  - `trim_by_retention`：按 `updatedAt`/`createdAt` 裁剪，**无时间戳的会话一律保留**；
  - `mask_enabled` / `retention_days`：读环境变量，异常值回落默认。
- `api/hub_accounts.py::save_user_conversations`：
  `trim_by_retention` → `mask_payload` → 40 条截断 → 写库。
- `scripts/purge_conversations.py`：按 `updated_at` 批量清理存量（默认 dry-run）。

## 4. 存量清理（运维）

```bash
# 1) 先看会删多少（默认 180 天）
python scripts/purge_conversations.py

# 2) 确认后执行
python scripts/purge_conversations.py --apply

# 3) 建议每月一次（crontab，凌晨低峰）
0 4 1 * * cd /data/zoujin/deng/zebrafish_gene_qa && \
  /data/zoujin/deng/miniconda3/envs/zebrafish/bin/python scripts/purge_conversations.py --apply \
  >> /data/zoujin/deng/zebrafish_runtime/logs/purge_conversations.log 2>&1
```

注意：`purge_conversations.py` 直接走主账号连接（写操作），
**不要**在只读账号上运行（只读账号执行 DELETE 会被数据库拒绝，属预期）。

## 5. 验收标准

1. 保存含 `a.user@example.com` / `13812345678` 的对话后，直接查库看到的是脱敏值。
2. 构造一个 `updatedAt` 为 200 天前的会话，保存后该会话不在库中，且日志出现
   `[历史] 按留存策略丢弃 1 个过期会话`。
3. `HUB_HISTORY_MASK_PII=0` 时，落库内容与原文一致（回滚验证）。
4. `HUB_HISTORY_RETENTION_DAYS=0` 时不裁剪（回滚验证）。
5. `purge_conversations.py` dry-run 的数字与实际删除行数一致。

## 6. 未覆盖 / 后续可做

| 项 | 说明 |
|---|---|
| 落库加密（KMS/Fernet） | 需密钥托管与轮换方案；当前策略是"少存 + 脱敏 + 限期"，性价比更高 |
| 用户自助导出/删除 | 前端已有"删除会话"，但没有服务端审计日志；如需合规存证要另立需求 |
| 审计日志 | 谁在什么时候读过别人的历史，目前只有 `role_can_admin` 的接口级控制 |
| 分级留存 | 目前全量 180 天；若未来区分"游客/注册用户"可给不同阈值 |
