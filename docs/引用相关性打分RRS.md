# 引用相关性打分方案 RRS（Reference Relevance Score）

> 2026-10-10 新增。解决的实际问题：问「斑马鱼 nanog 基因」时，文末参考文献里混进了
> 纳米颗粒 / 纳米塑料 / NgAgo 敲降等**与问句无关**的论文（它们来自跨库检索的证据池，
> 被「不足下限就从池里按序补齐」的旧逻辑带了进来）。

## 0. 与既有打分方案的关系

既有 `docs/paper/data_package/01_benchmark/rubric.md` 是**回答级** 7 维细则
（`direct_first` / `factor_structure` / `ge_formula` / `inline_cite` / `ref_count` /
`recency` / `no_review_shell`，满分 10）。其中 `inline_cite`、`ref_count`、`recency`
已经在管「引用这件事」，但只能事后打分，**不参与生成**。

RRS 沿用同一套设计哲学（显式权重 / 可复算 / 有下限），把对象换成**单条文献**，
并且它是**排序层的一道加权**——分值决定「谁排在前面、谁进 20~25 条的额度」，
另有一条硬排除（见 §2）管「谁绝对不该进来」。两者可以并存：
7 维细则继续管「回答写得好不好」，RRS 管「文末表挂哪些、按什么序」。

## 1. 维度与权重（满分 1.0）

| 维 | 权重 | 取值 | 为什么这么定 |
| --- | --- | --- | --- |
| `entity` 实体命中 | **0.30** | 问句里的基因符号/ID 在题名中按独立词命中 → 1.0；否则 0.0 | 最硬的证据。「查 A 基因却挂了 B 主题的论文」在这一维就露馅 |
| `rank` 证据池位次 | **0.15** | 绝对档位（≤3 / ≤8 / ≤15 / ≤25 / ≤40 → 1.0 / 0.85 / 0.7 / 0.5 / 0.35，其余 0.2）占 0.6 + 相对位次 `1-(n-1)/(N-1)` 占 0.4 | 证据池顺序是 4B 嵌入 + bge-reranker 的**综合**结果（含年份与 IF 的 blend），不等于纯语义相关度 |
| `rel` **连续语义相关度** | **0.10** | 证据池编号行里的 `rel=0.871`（0~1，来自 `rel_n`） | 上游算过但以前**只用于排序、分数没落盘** → 下游只能拿“名次”当代理（相邻名次的分数可能差很多，也可能几乎一样）。现已写出分数并单独成维 |
| `cite` 正文引用 | **0.20** | 正文出现过 `[n]` → 1.0；否则 0.0 | 模型确实用了这条证据，是最强的「被使用」信号 |
| `recency` 时效 | **0.15** | ≤5 年 1.0 / ≤10 年 0.8 / ≤20 年 0.5 / 更早 0.3 / 年不详 0.2 | 对齐 7 维细则里的 `recency` |
| `meta` 元数据完整 | **0.10** | DOI 0.4 + PMID 0.4 + 真实刊名 0.2 | 元数据全的条目可复核、能点原文；残缺条目容易是脏数据 |

**然后再加上「对数影响因子」加成（不是第六个权重维）**：

$$
RRS = \underbrace{0.30e + 0.15r + 0.10q + 0.20c + 0.15t + 0.10m}_{\text{六维归一化加权}（无实体时 e 权重按比例分摊）} + \underbrace{K \cdot \ln(1+IF)}_{\text{对数影响因子加成}}
$$

相关度总量仍是 **0.75**（`e 0.30 + r 0.15 + q 0.10 + c 0.20`）—— 把原来 `rank` 的 0.25 拆成
「位次 0.15 + 连续分 0.10」，因为位次里还混着年份与 IF 的 blend，不能把“名次”当纯相关度。

**拿不到 `rel=` 分数时**（旧证据池、Hub 小库路径）：`rel` 维的 0.10 自动退给 `rank`（→ 0.25），
总分尺度与改动前完全一致，不会因缺分数而整体变差（回归测试 H1 锁定）。

- **取对数就是它的全部意义**：IF 从 1.7（Zebrafish）到 50.5（Nature）是 30 倍，对数把它压成 4 倍 ——
  高刊能稳定排在「同等相关」的前面，又不会把离题的高分刊顶上来。
- `K` 只是**缩放系数**（`REF_RRS_IF_K`，默认 **0.01**）：Nature `ln(1+50.5)=3.94 → +0.039`，
  与检索层 blend 的 `w_if=0.04` 同一量级（同一个数量级，不是同一个算法）。
- **未知刊/无 IF 值 → 0**：不加成也不扣分（不会因为没查到刊名而被罚）。
- 本库 `journal_metric` 52 行实测：Nature 50.5・eLife 6.4・Development 4.6・PLOS ONE 2.9・Zebrafish 1.7。

## 2. 与原检索链的关系（定位：**加权精排层**）

原机制不动，RRS 插在「精排 100」之后：

```
FAISS 粗排 500  →  CrossEncoder 精排 100  →  【RRS 五维加权重排】取前 25/12  →  文末 20~25 条
```

它只做两件事：

1. **重排**：按加权分从高到低（实体 0.30 / 池内位次 0.25 / 正文引用 0.20 / 时效 0.15 / 元数据 0.10），
   只保留前 `REF_FOOTER_MAX` 条（机制题 **25**、事实题 **12**），下游再补到 `REF_FOOTER_MIN`（**20**）。
2. **一条硬排除**：问句点名了实体（基因符号/ID），而该条题名里**没有**这个实体、正文也**没引用**它
   → 剔除，**且永不在下游补回来**。`REF_RRS_HARD_ENTITY=0` 可关闭。
   → 这就是「问 nanog 却挂纳米颗粒/纳米塑料论文」的治法：那些条目标题里没有 nanog、正文也没引。
   → 换成「纳米颗粒对斑马鱼胚胎免疫的影响」这类问句时，纳米颗粒论文不受影响，
   因为闸门是**随问句变化**的，不是关键词黑名单。
3. **宁缺勿滥**：硬排除后不足 2 条则整块省略，并把正文里对应的悬空 `[n]` 清掉。

### 2.1 为什么不做「门槛淘汰」（2026-10-11 用户反馈后的修正）

曾把 `RRS ≥ 0.50` 当入选闸门（不合格直接丢）。实测两个问题：

1. 整池常被切成 0~3 条 → 下游 `len(use) < 2` 不成表 → **正文引用也一起被清**，
   表现就是用户看到的「引用怎么这么少了」；
2. 用户要的是**在原机制上升级**（FAISS 500 → 精排 100 → 加权 → 20~25 条），不是换一套规则。

改法：**门槛不参与默认流程**（`REF_RRS_MIN` 仅在显式传 `min_score=` 时生效，留给调试/回归），
分值只用于**排序**；数量由 `REF_FOOTER_MIN=20 / REF_FOOTER_MAX=25` 控制。
另外在 `api/api_server.py` 加了一道**全路径兜底** `_ensure_footer_any_path()`：
任何路径只要正文用了 `[n]` 却没生成参考文献段，就用证据池补出来（旧 `mode=rag` 路径曾经就是这种悬空状态）。

## 3. 无实体问句（表型 / 机制类）

纯中文表型问题（如「温度对斑马鱼性别分化的影响」）抽不出实体，此时：

- `entity` 维**不参与**，其权重按比例分摊给其余四维；
- 排序只看四维（满打满算 0.70），因此**不再有门槛误伤**问题 —— 这也是改成「只排序不淘汰」的另一好处。

## 4. 实体抽取（宁漏不误伤）

只认三类 token，且用**显式 ASCII 边界**（Python 的 `\b` 把中文也当词字符，
「斑马鱼nanog基因」里抓不出 `nanog`，这个坑踩过）：

1. 标识符：`ZDB-GENE-030131-5486`、`ENSDARG00000075113`、`WP…/R-DRE-…`
2. 含数字的短词：`tp53`、`pax6a`、`sox2`、`cd4`
3. 不含数字的小写短词且不在非实体词表里：`nanog`、`myod`

非实体词表（`_STOPWORDS`）刻意收得很宽，把 `zebrafish`、`gene`、`expression`、
`hypoxia`、`nanoparticle`、`inflammation` 这类**主题词**排除在实体之外——
它们描述话题，不是基因符号，一旦当实体就会变成硬门槛，误杀正常文献。

## 5. 环境变量

| 变量 | 默认 | 含义 |
| --- | --- | --- |
| `REF_RRS_MIN` | `0.50` | 有实体问句的筛选门槛——**默认流程已不用**（仅显式 `min_score=` 时生效） |
| `REF_RRS_MIN_NO_ENTITY` | `0.40` | 无实体问句的门槛——同上，默认不用 |
| `REF_RRS_HARD_ENTITY` | `1` | 是否启用实体硬规则（建议永远开） |
| `REF_FOOTER_MIN` | `20`（事实题 6） | 文末下限（这就是「最后展示 20~25 条」的下限） |
| `REF_FOOTER_MAX` | `25`（事实题 12） | 文末上限；同时是加权精排保留的条数 |
| `REF_RRS_IF_K` | `0.01` | 对数影响因子加成系数 K（`RRS += K·ln(1+IF)`）；只缩放加成，不动五维 |
| `REF_RRS_DEBUG` | `0` | 为 1 时逐条打印打分（含各维分值），便于复盘 |

关掉整套机制：`REF_RRS_MIN=0.05 REF_RRS_HARD_ENTITY=0`（退回「按池序补足」的老行为）。

## 7. 怎么调

- 觉得**太严**（该有的文献被挡）：先看 `REF_RRS_DEBUG=1` 的日志，
  常见原因是问句里的符号被误当实体 → 往 `_STOPWORDS` 加词；
  其次是门槛偏高 → 降 `REF_RRS_MIN`。
- 觉得**太松**（无关文献还进来）：提高 `REF_RRS_MIN`，或确认
  `REF_RRS_HARD_ENTITY=1`（第 2 条硬规则是最有效的一刀）。
- 觉得**引用条数少了**：先看是不是「整池不过门槛」——把 `REF_FOOTER_MIN` 调低会同步降低
  两段式补足的目标条数；如果是不相关的混进来了，优先靠 `REF_RRS_HARD_ENTITY` 拦，
  而不是把 `REF_FOOTER_MIN` 拉高（拉高只会把阈值外条目又按分数补回来，作用有限）。
