## 二、治理原则

1. **单一事实源**：每个"名称 → 基因"的关系只有一个地方能写，其他地方只能引用。
2. **官方优先**：符号与别名以 ZFIN 官方为准，NCBI / RefSeq / Ensembl / UniProt 只做补充；
   冲突时官方胜出，补充来源记入备注。
3. **一条名称一条记录**：不再把清单塞进 JSON 列，也不在多张表里各存一份。
4. **冲突显式化**：无法判定归属的名称写进冲突表，检索时明示"需人工确认"，不猜。
5. **可追溯**：任何清理都留旧值 + 原因 + 时间，能逐条回滚。

## 三、名称层方案（核心）

### 3.1 新建 `gene_name_index`

替代 `gene_alias` + `gene_name_bundle` 的双轨现状。

```sql
CREATE TABLE gene_name_index (
  id         INT AUTO_INCREMENT PRIMARY KEY,
  gene_id    INT NOT NULL,
  name       VARCHAR(200) NOT NULL,        -- 原样，用于展示
  name_norm  VARCHAR(200) NOT NULL,        -- 小写、去空格/连字符/点，用于匹配
  kind       VARCHAR(16)  NOT NULL,        -- symbol | synonym | former | full_name | xref
  source     VARCHAR(24)  NOT NULL,        -- zfin | ncbi | refseq | ensembl | uniprot | local
  rank       TINYINT      NOT NULL DEFAULT 50,  -- 同一 name 多来源时的可信度
  is_current TINYINT(1)   NOT NULL DEFAULT 1,   -- 0 = 旧名，仍可检索，展示时标"曾用名"
  created_at DATETIME DEFAULT CURRENT_TIMESTAMP,
  UNIQUE KEY uk_name_gene_src (name_norm, gene_id, source),
  KEY idx_name (name_norm),
  KEY idx_gene (gene_id)
) DEFAULT CHARSET=utf8mb4;
```

**写入规则**

| kind | 来源 | 取值 |
|---|---|---|
| symbol | zfin | `markers.txt` 的官方符号 |
| symbol | local | `gene_basic.gene_name`（与官方一致时只留一条） |
| synonym | zfin | `aliases.txt` 里该 ZDB ID 的别名 |
| synonym | ncbi | `gene_alias` 中 `source='ncbi' AND alias_type='synonym'` |
| full_name | refseq | `gene_alias` 中 `alias_type='full_name'` |
| former | zfin/dedup | `alias_type IN ('former','nomenclature')`，`is_current=0` |
| xref | 各库 | ZFIN / Ensembl / NCBI Gene / UniProt 的 ID |

**不写入**：自指（name_norm = 本基因 gene_name）、`-`、空串、长度 < 2 且无字母数字。

### 3.2 新建 `gene_name_conflict`

```sql
CREATE TABLE gene_name_conflict (
  id        INT AUTO_INCREMENT PRIMARY KEY,
  name_norm VARCHAR(200) NOT NULL UNIQUE,
  name      VARCHAR(200) NOT NULL,
  gene_ids  VARCHAR(400) NOT NULL,   -- 逗号分隔，按 rank 排序
  n_genes   INT NOT NULL,
  reason    VARCHAR(200),
  status    VARCHAR(16) DEFAULT 'open',  -- open | resolved | ignored
  resolved_to INT NULL,
  created_at DATETIME DEFAULT CURRENT_TIMESTAMP
) DEFAULT CHARSET=utf8mb4;
```

**判定顺序**（一个 name_norm 对应 2+ 基因时）：

1. 这些基因里有 `merged_into` 关系的 → 归到主记录，不算冲突
2. 同 ZFIN ID 或同 Ensembl ID → 视为同一基因的重复记录，归并
3. 名称来自官方别名且官方只指向一个 ZDB ID → 归那个
4. 其余 → 写冲突表，检索时进 `conflict` 层，文案"需人工确认"

### 3.3 检索层改造

`gene_match.search_classified` 从"三层 SQL 兜底"简化为查索引：

```sql
-- 同义命中
SELECT gene_id, kind, source FROM gene_name_index
 WHERE name_norm = :kw ORDER BY rank DESC;
```

- 命中即"同一基因"（不再需要用 `alias_role` 猜这串是不是描述型）
- 命中多个 gene_id 且该 name_norm 在冲突表里 → 直接进 `conflict`
- 前缀 / 包含这两层保留（它们是"不是同一个基因"的明确语义），但只在 `scope=all` 时跑

这样 `alias_role()`、`is_id_like()` 的猜测逻辑可以退化成"索引写入时的分类"，一次做对，
而不是每次查询都猜。

### 3.4 废弃 `gene_name_bundle`

它现在是"半张表 + 五个 JSON 列"，且数据停在 9 月 16 日。索引表建好后：

1. 检索不再 join 它（`_SELECT` 去掉 `gene_name_bundle`）
2. 观察一周无引用后 `RENAME TABLE gene_name_bundle TO _archive_gene_name_bundle`

## 四、表结构与冗余清理

### 4.1 备份表归档

6 张一次性备份表（含本次新增的 4 张）迁到 `zebrafish_archive` 库，保留 30 天：

```sql
CREATE DATABASE zebrafish_archive;
RENAME TABLE zebrafish_db.gene_basic_bak_cleanup20261104
          TO zebrafish_archive.gene_basic_bak_cleanup20261104;
```

主库只保留**当前有效**的表，盘点时不再被 34 万行备份干扰。

### 4.2 坐标表定主从

```
grcz12tu_gene            主表（53,513，RefSeq GRCz12tu 原生）
gene_master_grcz12tu     派生（53,359，聚合视图性质，加注释说明）
其他坐标副本             若无引用，归档
```

在表注释里写清"谁是主、谁是从、从谁派生"，避免下次再有人往副本里写。

### 4.3 废列标记

`gene_basic.interpro_domain` 非空 0.1%，实际未使用。加注释 `-- DEPRECATED 2026-11-04`，
不删列（删列会影响 `SELECT *` 的脚本），下个大版本再移除。

## 五、执行阶段

| 阶段 | 内容 | 风险 | 回滚 |
|---|---|---|---|
| P0 ✅ | ZFIN 多挂、错挂别名（已完成） | 中 | 备份表 + `zfin_id_old` + 审计日志 |
| P1 | 建 `gene_name_index` / `gene_name_conflict`，写重建脚本，**只读双跑对账** | 低 | 新表可整表 DROP |
| P2 | 检索切到索引表，与旧逻辑并行比对（同 query 比条数与 gene_id 集合） | 中 | 开关切回旧路径 |
| P3 | 废弃 bundle、备份表归档、坐标表定主从 | 低 | RENAME 可逆 |
| P4 | 把重建脚本挂进定时任务（每周日），与 ZFIN 官方对账 | 低 | 只影响索引表 |

**P1 的验收（建表后必须全绿才进 P2）**

- 索引表行数 ≈ 现 `gene_alias` 去掉自指与垃圾后的行数（预计 11 万以内）
- `SELECT name_norm, COUNT(DISTINCT gene_id) FROM gene_name_index GROUP BY 1 HAVING 2 > 1`
  的结果，与 `gene_name_conflict` 的 `open` 条数一致（没有漏网的歧义）
- 抽样 50 个基因，索引里的名称集合 ⊇ 现 `gene_alias` 的集合（不丢名字）

**P2 的验收**

对 200 个真实查询（符号 / 别名 / 旧名 / 跨库 ID / 垃圾串各 40 个），逐条比对：

- `scope=same` 返回的 gene_id 集合与旧逻辑一致（可多不可少）
- `scope=all` 的 `conflict` 层条数不增加
