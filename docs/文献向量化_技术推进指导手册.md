# PubMed「是」文献向量化 — 技术推进指导手册

> 版本：v1.0 · 2026-08-01  
> 适用范围：本仓库「判别为是」的斑马鱼主研究文献 → 分片 FAISS 向量库  
> 设计对照：马铃薯知识中枢（Li et al., *Plant Communications* 2026）RAG 实践  
> 配套代码：`scripts/fetch_pubmed_yes_corpus.py`、`scripts/vectorize_pubmed_judgement_yes.py`  
> 配套方案：`docs/pubmed_judgement_yes_vectorization_plan.md`

---

## 0. 目标与边界

### 0.1 交付目标

| 交付物 | 说明 |
|--------|------|
| 规范化语料 | `data/literature/pubmed_yes_corpus.jsonl`（一篇一行，含标题/摘要/可选全文） |
| 分片向量索引 | `%LOCALAPPDATA%\ZebrafishGeneQA\faiss_pubmed_yes\shard_XXXX\` |
| 分片清单 | 同目录 `manifest.json` |
| Chunk 元数据 | MySQL 表 `literature_vector_chunk`（不存向量本体） |
| 可检索接口 | `rag.pubmed_yes_retriever.PubmedYesRetriever` |
| 进度文件 | `data/literature/pubmed_yes_fetch.json`、`pubmed_yes_vectorize.json` |

### 0.2 明确不做（一期）

- 不把 Hub 小知识库 `faiss_index` 与 YES 大库混建（两套索引分离）
- 不引入 Chroma / Milvus（一期坚持 FAISS 分片）
- 不批量抓取付费墙 PDF（合规与成本；二期用已有金标/OA 全文增量）
- 不调用 DeepSeek 做嵌入（本地 `bge-small-zh-v1.5`）

### 0.3 与马铃薯知识中枢的对照（指导原则）

| 环节 | 马铃薯论文做法 | 本仓库一期落地 | 二期对齐方向 |
|------|----------------|----------------|--------------|
| 语料筛选 | 检索 → 期刊分区 → LLM 剔无关 → 人工 | 已有判别「是」子集 | 保持；可用金标全文升级 |
| 正文来源 | 全文 PDF→纯文本 | 摘要为主，可选 PMC OA | 接入 `yes_fulltext_gold` / pdf库金标 |
| 清洗 | 去作者/单位/参考文献/致谢 | `format_bilingual_document` 结构化模板 | 强化段落清洗 |
| 切分 | **自然段切分**最优 | 递归切分 **768 / overlap 80** | 评测后可切自然段 |
| 检索 | 向量 top≈200 → **重排** → top10 | 多分片 top-k 合并 | 加 bge-reranker / cross-encoder |
| 评测 | 70 题 + LLM-as-judge | 人工 query 抽检 + 固定题集 | 建斑马鱼领域评测集 |

## 1. 总体架构与数据流

```
判别「是」CSV / MySQL
        │
        ▼
┌──────────────────────┐
│ 阶段 A：语料获取       │  fetch_pubmed_yes_corpus
│ MySQL XML → NCBI/EPMC │  → pubmed_yes_corpus.jsonl
└──────────┬───────────┘
           ▼
┌──────────────────────┐
│ 阶段 B：规范化 + 分块  │  format_bilingual_document
│ 中英标题摘要(+全文)    │  RecursiveCharacterTextSplitter(768/80)
└──────────┬───────────┘
           ▼
┌──────────────────────┐
│ 阶段 C：嵌入 + 落盘    │  BgeEmbedding → FAISS.from_documents
│ 每 shard 约 5000 篇   │  + literature_vector_chunk
└──────────┬───────────┘
           ▼
┌──────────────────────┐
│ 阶段 D：检索验收       │  PubmedYesRetriever.search / --phase test
└──────────────────────┘
```

**关键路径（默认）：**

| 用途 | 路径 / 配置键 |
|------|----------------|
| 嵌入模型 | `models/bge-small-zh-v1.5`（`rag/rag_builder.py`） |
| YES FAISS 根目录 | `FAISS_PUBMED_YES_DIR` → `%LOCALAPPDATA%\ZebrafishGeneQA\faiss_pubmed_yes` |
| Hub FAISS（勿混用） | `FAISS_INDEX_DIR` → `...\faiss_index` |
| 主语料 | `data/literature/pubmed_yes_corpus.jsonl` |
| 并发 fetch 分片 | `data/literature/pubmed_yes_corpus_shards/wXX.jsonl` |
| 判别源 CSV | `项目阶段/05_数据与库/归档/data_export/pubmed_judgement_full/` 下「是」表（见 `rag/pubmed_yes_source.py`） |
| 每片论文数 | `PUBMED_YES_SHARD_PAPERS=5000` |
| Chunk | `PUBMED_YES_CHUNK_SIZE=768`，`PUBMED_YES_CHUNK_OVERLAP=80` |
| Embed batch | `PUBMED_YES_EMBED_BATCH=64` |
| 字段权重 | title=2.0 / abstract=1.5 / body=1.0 / meta=0.7 / mixed=1.2 |
| 查询扩写 | `PUBMED_YES_QUERY_EXPAND=1`（HIF/线粒体等中英扩写） |
| 切块模块 | `rag/pubmed_yes_chunking.py`（分字段 title/meta/abstract/body） |

## 3. 阶段 A：语料获取（Fetch）

### 3.1 目的

把「是」文献变成统一 JSONL：`pmid / title_zh / title_en / abstract_zh / abstract_en / doi / journal / year / has_fulltext / fulltext?...`

优先级（代码内）：本地 MySQL `raw_xml` → NCBI efetch → Europe PMC（可选全文）。

### 3.2 推进步骤

#### A1. 冒烟（强制）

```powershell
python -m scripts.fetch_pubmed_yes_corpus --resume --limit 50
```

**验收：**

- 生成 `data/literature/pubmed_yes_corpus.jsonl`（或 shards）
- 抽 3 行：`pmid` 非空，至少有中/英标题或摘要之一
- 进度文件 `data/literature/pubmed_yes_fetch.json` 有更新

#### A2. 摘要全量（一期推荐默认）

```powershell
# 只要摘要、加快、少踩网络限流
python -m scripts.fetch_pubmed_yes_corpus --resume --skip-fulltext
```

#### A3. 带 PMC OA 全文（可选增强）

```powershell
python -m scripts.fetch_pubmed_yes_corpus --resume
```

#### A4. 多 worker 加速（可选）

```powershell
# 终端 1
python -m scripts.fetch_pubmed_yes_corpus --resume --worker-id 0 --workers 4
# 终端 2
python -m scripts.fetch_pubmed_yes_corpus --resume --worker-id 1 --workers 4
# … worker-id 2、3

# 合并分片到主 jsonl（若脚本提供/或使用 pubmed_yes_corpus_io.merge_shards_to_main）
python -c "from rag.pubmed_yes_corpus_io import merge_shards_to_main; print(merge_shards_to_main())"
```

### 3.3 Fetch 阶段门禁

| 指标 | 一期通过线 | 说明 |
|------|------------|------|
| 唯一 PMID 覆盖率 | ≥ **95%** 判别「是」总数 | `count_unique_pmids() / count_pubmed_yes_pmids()` |
| 空摘要率 | ≤ **5%** | 无摘要篇可二期补 |
| JSONL 可解析率 | **100%** | 坏行需清理 |
| 进度可 resume | 中断后 `--resume` 不重头 | 抽查 fetch 进度 JSON |

```powershell
python -c "from rag.pubmed_yes_source import count_pubmed_yes_pmids; from rag.pubmed_yes_corpus_io import count_unique_pmids; t=count_pubmed_yes_pmids(); d=count_unique_pmids(); print(d, t, round(100*d/t,2) if t else 0)"
```

**未达门禁：不要进入 Embed。**

## 4. 阶段 B：向量化（Embed）

### 4.1 单篇进入嵌入的文本形态

由 `rag/pubmed_corpus_utils.format_bilingual_document` 生成双语结构化文档，再按 768/80 切块。  
每块 metadata 至少含：`pmid`、`title_zh`、`has_fulltext`、`chunk_index`、`source=pubmed_yes`。

### 4.2 推进步骤

#### B1. 小规模嵌入冒烟（强制）

```powershell
python -m scripts.vectorize_pubmed_judgement_yes --phase embed --resume --limit 100
```

**验收：**

- 出现目录：`%LOCALAPPDATA%\ZebrafishGeneQA\faiss_pubmed_yes\shard_0000\`
- 含 `index.faiss`、`index.pkl`
- `manifest.json` 有 `total_papers` / `total_chunks`
- `data/literature/pubmed_yes_vectorize.json` 状态为 `running` 或 `completed`
- MySQL `literature_vector_chunk` 有对应 pmid 行（若表已建）

#### B2. 检索冒烟（强制，紧接 B1）

```powershell
python -m scripts.vectorize_pubmed_judgement_yes --phase test --query "斑马鱼 tp53 胚胎"
```

**验收：** 返回 ≥1 条命中，含 PMID 与可读文本片段；score 有数值。

#### B3. 全量嵌入

```powershell
python -m scripts.vectorize_pubmed_judgement_yes --phase embed --resume
```

或一条龙（fetch+embed）：

```powershell
python -m scripts.vectorize_pubmed_judgement_yes --phase all --resume
```

#### B4. 过夜托管（可选）

```powershell
python -m scripts.launch_overnight_pubmed_yes_vectorize
# 或强制重启
python -m scripts.launch_overnight_pubmed_yes_vectorize --force

# 看门狗（若 bat/worker 已配置）
pythonw -m scripts.overnight_pubmed_yes_vectorize_watchdog
```

> 注意：若 `logs/run_pubmed_yes_vectorize_worker.bat` 缺失，先用前台 `--phase embed --resume` 或自行补 bat，勿盲启 detach。

### 4.3 推倒重来（慎用）

```powershell
python -m scripts.vectorize_pubmed_judgement_yes --reset-embed
python -m scripts.vectorize_pubmed_judgement_yes --phase embed --no-resume
```

会清空 FAISS 目录与 chunk 表相关数据，**先备份**再执行。

### 4.4 Embed 阶段门禁

| 指标 | 通过线 |
|------|--------|
| `papers_done` ≈ 语料唯一篇数 | 差距 ≤ 1% |
| 每篇平均 chunks | 约 1.5–4（摘要）；全文会更高 |
| 坏 shard | 0（缺 index.faiss 的 shard 需重跑该片） |
| test 查询 5 条领域题 | 至少 4 条能命中相关 PMID/主题 |

**性能粗估（CPU + bge-small，摘要模式）：** 约 3–8 小时量级（视篇数与机器）；GPU 会明显加快。

## 5. 阶段 C：质量验收与评测（对齐马铃薯思路）

### 5.1 自动化抽检

```powershell
python -m scripts.vectorize_pubmed_judgement_yes --phase test --query "斑马鱼 心脏 发育"
python -m scripts.vectorize_pubmed_judgement_yes --phase test --query "crispr danio rerio"
python -m scripts.vectorize_pubmed_judgement_yes --phase test --query "tp53 apoptosis zebrafish"
```

### 5.2 人工评测集（建议新建，二期硬化）

准备 **30–70** 道领域题（基因功能 / 表型 / 通路 / 实验方法），每题标注：

- 期望应命中的 PMID 或关键词  
- 参考答案要点  

评分可参考马铃薯四维：**准确性 40 / 完整性 30 / 相关性 20 / 清晰度 10**（可先人工，后接 LLM-as-judge）。

### 5.3 切分与检索参数实验（可选，对齐论文）

在固定评测集上对比：

| 实验组 | 切分 | 检索 |
|--------|------|------|
| 基线（当前） | 768/80 | 分片 merge top-k |
| 对照 1 | 512/50 | 同左 |
| 对照 2 | 自然段切分 | 同左 |
| 对照 3 | 自然段 | + rerank → top10 |

**决策规则：** 评测均分提升 ≥ 3 分或失败题显著减少，再改默认配置（改 `PUBMED_YES_CHUNK_*` 或代码切分器）。

## 6. 阶段 D：接入问答 / 智能体

### 6.1 代码侧

```python
from rag.pubmed_yes_retriever import PubmedYesRetriever

r = PubmedYesRetriever()
hits = r.search("tp53 斑马鱼 突变表型", top_k=10)
ctx = r.get_context("tp53 斑马鱼 突变表型")  # 若提供
```

### 6.2 产品侧推进

1. Hub 编排（`agent/hub_orchestrator.py`）增加「文献库」工具：优先 YES FAISS，次选 Hub `faiss_index`  
2. 回答强制带 **PMID / 标题** 引用  
3. 会话问题改写（马铃薯做法）→ 再检索  
4. （二期）重排后取 top10 再生成  

### 6.3 接入门禁

| 条件 | 要求 |
|------|------|
| 检索延迟 | 单次 query P95 ≤ 3s（CPU） |
| 引用可追溯 | 每条 hit 有 pmid |
| 与 Hub 不串库 | YES 查询不读写 `faiss_index` |

## 7. 阶段 E：二期增强（全文与马铃薯对齐）

按优先级推进，**不要阻塞一期上线**：

| 顺序 | 工作项 | 输入 | 产出 |
|------|--------|------|------|
| E1 | OA/金标全文增量 | `yes_fulltext_gold`、`pdfku` 金标 JSON、`has_fulltext` | 对已有 pmid 重嵌或追加 chunk |
| E2 | 科学正文清洗 | 去参考文献/致谢/页眉 | 降低噪声命中 |
| E3 | 自然段切分 | 评测通过后改默认 | 更新 CHUNK 策略 |
| E4 | Reranker | bge-reranker 或 cross-encoder | 最终 top10 |
| E5 | 基因实体归一 | 对标马铃薯基因库 | 独立表 + 工具，不塞进向量 |

全文增量原则：**只升不降**——新全文 chunks 写入新 shard 或重建该 pmid 所属 shard；保留摘要 chunks 可用 `has_fulltext` 过滤偏好。

### 8.2 与金标战役共存策略

| 场景 | 策略 |
|------|------|
| 白天办公 / 游戏 | 暂停金标或静音；向量化 `--limit` 小批 |
| 夜间 | 向量化全量 **或** 金标全速，**二选一优先**，避免风扇与 OOM |
| 向量化进行中 | 勿 `--reset-embed`；勿删 corpus jsonl |

### 8.3 常见故障

| 现象 | 原因 | 处理 |
|------|------|------|
| `语料不存在` | 未 fetch | 先跑阶段 A |
| embed 极慢 | CPU + 全量 | 降 `PUBMED_YES_EMBED_BATCH` 或上 GPU；过夜跑 |
| FAISS AVX 报错 | CPU 指令集 | 保持 `FAISS_DISABLE_AVX2=1` |
| MySQL 写 chunk 失败 | 表不存在/权限 | 建表（见方案文档 SQL）或修权限后重跑该 shard |
| 检索为空 | 未 embed / 路径错 | 检查 `FAISS_PUBMED_YES_DIR` 与 manifest |
| resume 不前进 | 进度文件损坏 | 备份后对照 corpus 手工改 `last_shard_done`，或单 shard 重建 |
| 多进程写同一 jsonl | worker 冲突 | 使用 `--worker-id/--workers` 分片，最后 merge |

## 11. 完成定义（Definition of Done）

一期向量化模式视为**完成**，当且仅当：

1. 「是」文献语料唯一 PMID 覆盖率 ≥ 95%  
2. FAISS 分片齐全，`manifest.total_papers` 与语料一致（允许 ≤1% 差）  
3. `--phase test` 对 ≥5 条领域查询均有合理命中  
4. `PubmedYesRetriever` 可在代码中稳定调用并返回 pmid  
5. 进度文件可解释、可 `--resume`  
6. 文档与本手册路径/命令一致，新人可按阶段 0→D 独立跑通  

二期「马铃薯对齐完成」另需：自然段或等效切分评测胜出、重排 top10、至少一批金标全文增量入库。
