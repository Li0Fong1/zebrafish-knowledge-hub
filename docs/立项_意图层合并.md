# 立项：合并两套意图识别（单一事实源）

> 状态：已实施并上线。
> 关联审计项：可维护性 #17「两套并行意图识别」。

## 1. 问题

同一句话有两个入口各自判断该调哪个工具：

| 位置 | 能力 | 被谁调用 |
|---|---|---|
| `chat_understanding.task_specs()` | 一句话拆多个维度（坐标+表达+别名…） | `answer_with_tool` 主路径 |
| `chat_tool_dispatch.detect_tool_intent()` | 单意图，规则独立维护（约 80 行） | 仅在主路径没命中时"兜底" |

后果：

1. **结论可能不一致** —— 同一句「tp53 的坐标及表达」，新层给 2 个维度，旧层给 1 个；
2. **改一边漏一边** —— 前几轮反复出现的「只答一半」，本质就是关键词只补在某一边；
3. 排查时要同时读两套规则，理解成本高。

## 2. 合并前的差分验证

删代码之前先证明"旧层能命中的，新层都能命中"：

- 基因 × 维度 × 动作词组合（5 基因 × 13 尾缀 × 6 前缀 = 390 条）；
- 区间 / 序列 / BLAST / 表型反向检索 / 英文问法 / ID 互转等 18 条真实问法；
- 判定标准：`detect_tool_intent(q) is not None and not task_specs(q)` 记为 GAP。

结果：**GAP = 0**。新层是旧层的严格超集。

## 3. 改动

```python
# database/chat_tool_dispatch.py
def detect_tool_intent(question: str) -> Optional[dict]:
    """兼容旧调用：返回第一个子任务；无意图返回 None。"""
    specs = task_specs(question)
    return specs[0] if specs else None
```

- 删除原 80 行独立规则与 `_HARD_MECHANISM` 常量；
- `answer_with_tool` 不再有"新层没命中就回退旧层"的分支：
  命中即执行，未命中直接交回原链路（大模型 / 文献）；
- 定义类逃逸（"sgRNA 是什么"）无需单独兜底 —— `task_specs` 在无对象时本就返回空。

## 4. 为什么不是反过来（旧层保留、新层适配）

旧层是**单意图**结构，天然表达不了「坐标 + 表达 + 别名」；把新层降级成单意图会直接
让"回答不全"回归。方向只能是"多维度为主、单意图做兼容壳"。

## 5. 验收

1. `tp53的坐标及表达` → `['gene_locus','expression']`（双维度）。
2. `tp53 的引物` → `['primer']`；`tp53 一键注释` → `['annotate']`。
3. `sgRNA 是什么` / `what is sgRNA` → `[]`（交回大模型）。
4. `detect_tool_intent()` 作为兼容壳，返回值恒等于 `task_specs()[0]`。
5. 线上 `/api/chat` 抽检 5 类问法，`tools_invoked` 与合并前一致或更全。
