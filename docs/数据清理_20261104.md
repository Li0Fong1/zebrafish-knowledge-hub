## 二、问题一：一个 ZFIN ID 挂在 2+ 条记录（61 组、126 条）

### 判定规则

组内打分选真身：记录名 = 官方符号 +100；`gene_symbol` = 官方符号 +60（symbol 字段
常被错挂的 ID 抄脏，权重低）；NCBI GeneID 一致 +40；有 Ensembl +8；有染色体 +3。

副记录（非真身）先按自己的名字去官方反查真 ID：
- 唯一且未被占用 → **改正**（fix）
- 查不到 / 候选冲突 → **清空**（clear）

### 结果

| 动作 | 条数 | 说明 |
|---|---|---|
| keep | 60 | 组内真身，保持不动 |
| fix | 17 | 改成 ZFIN 官方对应的真 ID |
| clear | 49 | 该 ID 应属同组另一条，清空 |

改正样例（新 ID 在 ZFIN 官方的符号与记录名逐条核对一致）：

```
sox9b             ZDB-GENE-040625-1   -> ZDB-GENE-001103-2   官方=sox9b
fgf8a             ZDB-GENE-990603-1   -> ZDB-GENE-990415-72  官方=fgf8a
nkd2a             ZDB-GENE-081013-6   -> ZDB-GENE-071130-1   官方=nkd2a
ugt2b3            ZDB-GENE-100402-1   -> ZDB-GENE-100402-2   官方=ugt2b3
casp3l            ZDB-GENE-070607-1   -> ZDB-GENE-240410-3   官方=casp3l
```

清空样例：`her9`(保留 hes4)、`ncl`(保留 nucleolin)、`cxcr7`(保留 ackr3b)、
`lrh1`(保留 nr5a2)、`fxr`(保留 nr1h4)。

**有一组整组清空**：`ZDB-GENE-080218-7` 官方符号是 `znf1085`，但本地两条记录
（`si:ch211-91b17.1`、`znf1087`）都不是它，且本地没有 znf1085 —— 这个 ID 谁都不该占。

### 附带修掉：62 个根本不存在的 ZFIN ID

`mapk1` 挂着 `ZDB-GENE-000210-14`、`scn1lab` 挂着 `ZDB-GENE-000210-9`。
按名字反查可唯一确定的 12 条已改正（`mapk1` → `ZDB-GENE-030722-2`），
其余 50 条（多为线粒体 tRNA）列入 `cleanup_orphan_zfin` 待核，未动。

## 三、问题二：别名恰好等于另一个基因的正式符号（816 条 → 处理 863 行）

`gene_alias` 143,373 行里，816 条别名的字符串正好是**另一个基因**的正式符号。
样本呈现明显的**管道错位**特征：

```
alias=ndr1  挂在 ndr2      ←→  alias=ndr2  挂在 ndr1   （212 对互挂）
alias=actb1 挂在 actb2
alias=calcr 挂在 shha
alias=her6  挂在 hes1
```

### 结论：删除优于「改正到正确位置」

| 判据 | 说明 |
|---|---|
| 目标已有该入口 | 765/816 条的目标基因名下本来就有同名条目，它的正式符号就是该串 |
| 改正等于复制 | 迁移后只是给目标基因加一条**指向自己**的别名，检索零增量 |
| 歧义仍在 | 迁移后两条记录都留着该串，搜一次仍然出两个基因 |
| 删除可消除歧义 | 搜 `actb1` 只命中 actb1，不再连带 actb2 |

因此：**不同基因的错挂别名删除**；**同一基因两条记录之间的别名保留**。

| 动作 | 条数 | 依据 |
|---|---|---|
| delete | 758 | 该符号已归另一个基因，且目标记录是有实体（有坐标/ZFIN/蛋白）的记录 |
| keep | 104 | 挂靠与目标实为同一基因（同 ZFIN 或同 Ensembl），别名是合法的旧名入口 |
| keep | 1 | 目标记录是空壳（`env`→`erv`），删了会让该名字无处可去 |

保留的 104 条举例：`her6`→`hes1`、`cxcr7`→`ackr3b`、`fxr`→`nr1h4`、`ntla`→`tbxta`。
这些是旧名/新名的正常登记，删掉反而会丢失按旧名检索的路径。

## 四、配套改动：不能让清理造成回退

清空副记录的 zfin_id 后，原先「靠同一个 ZFIN ID 判定同基因」的合并逻辑失效，
`her6` 会重新显示成两行。为此：

1. `gene_basic` 新增 `merged_into`（INT，指向主记录 gene_id），只对**同染色体或
   无坐标冲突**的 40 条设置；染色体不同的 9 组不设（`ntla` chr9 / `tbxta` chr19
   仍单列，属于待人工核对的坐标问题）
2. `gene_match._merge_dupes` 优先按 `merged_into` 判键，主记录也归到同一键
3. 新增跨层去重：同一基因的副记录落在不同层级时（`cxcr7` 在 exact_symbol、
   `ackr3b` 在 conflict），只在最高层显示一次，缺的字段互补过去

效果：

```
her6  -> exact_symbol 1 行: hes1（zfin 补自 464，merged_gene_ids=[21058]）
cxcr7 -> exact_symbol 1 行: cxcr7（zfin 补自 ackr3b，merged_gene_ids=[2872]）
ntla  -> exact_symbol ntla + conflict tbxta（染色体不同，不合并，保留提示）
```

## 六、回滚

```sql
-- 1) 整表还原
UPDATE gene_basic b JOIN gene_basic_bak_cleanup20261104 k ON k.gene_id=b.gene_id
   SET b.zfin_id=k.zfin_id, b.merged_into=NULL;
-- 2) 或按列还原（只回滚本次改过的 78 条）
UPDATE gene_basic SET zfin_id=zfin_id_old WHERE zfin_id_old IS NOT NULL;
-- 3) 恢复被删别名
INSERT INTO gene_alias SELECT * FROM gene_alias_deleted_20261104;
-- 4) 恢复 gene_xref
DELETE FROM gene_xref WHERE db_name='zfin';
INSERT INTO gene_xref SELECT * FROM gene_xref_bak_cleanup20261104 WHERE db_name='zfin';
```

备份表：`gene_basic_bak_cleanup20261104`（32,139）、`gene_alias_bak_cleanup20261104`
（143,373）、`gene_xref_bak_cleanup20261104`（101,384）、
`gene_alias_deleted_20261104`（758）。审计：`gene_cleanup_log`（837 条，逐条记录老值新值）。
