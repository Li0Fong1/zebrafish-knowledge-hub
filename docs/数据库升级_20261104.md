## 二、修掉的三类问题

### 1. 一次性备份表滞留在主库

6 个历史清理批次留下 9 张备份表，和业务表混在一起，盘点时看不出哪些是活的。

处理：迁到新建的 `zebrafish_archive` 库（`RENAME TABLE`，原子且可逆）。

```
_dedup_map_dedup20261103                425 行
gene_alias_bak_dedup20261103        145,439 行
gene_alias_bak_cleanup20261104      143,373 行
gene_assembly_xref_bak_dedup20261103 29,493 行
gene_basic_bak_cleanup20261104       32,139 行
gene_basic_bak_dedup20261103         32,564 行
gene_basic_uniprot_bak_20261031      32,564 行
gene_xref_bak_cleanup20261104       101,384 行
name_hit_unique_bak_dedup20261103   133,677 行
```

### 2. `gene_basic` 与 `gene_xref` 的 ZFIN 标识不同步

| 症状 | 条数 |
|---|---|
| `gene_basic` 有 ZDB-GENE 标识，`gene_xref` 没有对应行 | **8,197** |
| `gene_xref` 里的 ZDB-GENE 与 `gene_basic` 不一致 | **33** |

后果：按 ZFIN ID 做 ID 映射时，这批基因查不到或查到错的。

处理：以 `gene_basic` 为准（11-04 按 ZFIN 官方清理过）——先删 33 条不符的，再补 8,197 条，`source='sync20261104'` 留痕。

> 顺带修正了一个校验误报：`gene_xref` 的 `db_name='zfin'` 混有 `ZDB-MIRNAG` / `ZDB-LINCRNAG` 等非基因 marker，这些是有效标识、不是缺漏。校验必须限定 `ZDB-GENE-` 前缀。

### 3. 名称解析层停在 9 月

`gene_name_bundle` 只有 25,896 行，比 `gene_basic` 少 6,243 个基因；`name_hit_unique` / `name_resolve_collision` 也是同一批旧数据。

处理：用项目自带的 `scripts/build_name_resolve_layer.py` 整层重建（单事务 DELETE+INSERT，读请求期间看到的仍是旧数据）。

| 表 | 升级前 | 升级后 |
|---|---|---|
| `gene_name_bundle` | 25,896 | **32,139**（与主表一致） |
| `name_hit_unique` | 133,677 | **142,538** |
| `name_resolve_collision` | 6,129 | **3,438**（歧义减少 44%） |

## 六、回滚

```sql
-- 1) 表移回主库
RENAME TABLE zebrafish_archive.gene_alias_bak_dedup20261103
          TO zebrafish_db.gene_alias_bak_dedup20261103;   -- 其余 8 张同理

-- 2) 名称层还原（升级前备份）
DELETE FROM gene_name_bundle;
INSERT INTO gene_name_bundle SELECT * FROM zebrafish_archive.gene_name_bundle_bak_20261104;
-- name_hit_unique / name_resolve_collision 同样处理

-- 3) gene_xref 还原
DELETE FROM gene_xref WHERE source='sync20261104';
INSERT INTO gene_xref SELECT * FROM zebrafish_archive.gene_xref_bak_cleanup20261104
 WHERE gene_id NOT IN (SELECT gene_id FROM gene_xref);   -- 补回被删的 33 条

-- 4) 索引/注释
ALTER TABLE legacy_genome_feature DROP INDEX idx_zfin, DROP INDEX idx_ensembl, DROP INDEX idx_chrom;
```

备份：`zebrafish_archive` 库（9 张表 + 3 张名称层快照，合计约 68 MB）。

## 八、补充：名称类型标记（20:20 追加）

`gene_basic` 新增 `name_kind` 列，把「有正式符号的基因」与「未命名记录」分开：

| `name_kind` | 条数 | 含义 |
|---|---|---|
| `symbol` | **21,088** | 正式基因符号，对外报「基因数」用这一档 |
| `clone` | 7,493 | 克隆 / EST 号（`si:` `wu:` `zgc:` `im:`）|
| `ensembl_id` | 1,839 | 以 `ENSDARG…` 编号代名 |
| `zfin_id` | 1,627 | 以 `ZDB-GENE-…` 编号代名 |
| `loc` | 92 | `LOC` + 数字，RefSeq 占位名 |

迁移脚本：`sql/gene_name_kind_migration.sql`

此后统计不再写 `NOT LIKE` 条件，统一按 `name_kind` 分组：

```sql
-- 基因数
SELECT COUNT(*) FROM gene_basic WHERE name_kind = 'symbol';   -- 21,088
-- 记录数
SELECT COUNT(*) FROM gene_basic;                              -- 32,139
-- 构成
SELECT name_kind, COUNT(*) FROM gene_basic GROUP BY name_kind;
```
