一、怎么查的

「功能回答是否正确」有两个可能失真的方向：答文可能说错，也可能说的是别的页面。所以查三遍，各自独立：

层面查什么做法
① 事实基准页面真实能力 读 web/index.html 的面板（输入框、下拉、按钮、占位文案里的上限）、 web/js/page-meta.js 的数据卡（记录数、口径）、以及每个页面自己的接口； 对「到底用哪个库 / 哪些来源」这类易错项，直接调线上接口看返回值，不靠代码注释推断。
② 离线路由 + 答文识别与内容 43 条问题过 classify_question_intent / is_hub_product_howto_question / detect_product_page / answer_hub_product_howto， 判定「是否进产品车道 + 认出的页面是否正确 + 答文是否含本页必备要点」。
③ 线上端到端用户真正收到什么 42 条打 POST /api/chat，检查 HTTP 200、是否命中产品短路、答文是否含要点； 另跑 17 项接口实证，确认「答文里说的能力」在系统里真的存在。
为什么要反向对照：把「怎么用/在哪/最多/什么版本」这类问法放宽，很容易顺手把 「BLAST 的 E 值怎么理解」「tp53 在哪些组织表达」也吞掉。所以固定 10 条科学问题做反向对照， 要求一条都不能被当成界面问题——修复前后都是 0 误伤（见第五节）。

三、发现的问题与修复

P0问「GO 富集页怎么用」回的是聊天与序列说明answer_hub_product_howto 只有「序列类 / 通用类」两套固定文案，18 个页面共用；命中序列关键词就返回序列说明，其余一律返回同一段通用话术新增 llm/product_pages.py：18 个功能页各写一条事实（入口 / 输入 / 输出 / 上限 / 口径 / 不在本页做什么），按页面定位作答；认不出页面时给「功能地图」而不是含糊话术
P036 个页面提问里 29 个根本没被识别为「产品问题」识别只靠 _PRODUCT_HOWTO_RE（怎么用/在右侧/界面上…）+ 主题词，「GO 富集用什么统计方法」「BLAST 一次最多几条」「别名页能查跨库 ID 吗」都不命中，落进通用车道由大模型凭印象回答新增 detect_product_page()：用页面别名正则认页（按长名优先排序），再用 _PAGE_USAGE_RE 判断是否在问用法/参数；两条同时成立才进产品车道

P1BLAST 答成「转录组库 + 基因组库」，像是有两个库可选界面没有选库开关；_pick_blast_fasta() 只取 GRCz12tu RNA/CDS，实测返回 database=grcz12tu_cds.fna。genome_db 是 sgRNA/引物的脱靶库答文改成「比对库是 GRCz12tu CDS，没有选库开关」，并说明 genome_db 的归属；补上单条 ≤50 kb
P2能力自述漏项与措辞不准「KEGG 与 Reactome 通路」漏了 WikiPathways（tp53 卡片 33 条 = 9 + 19 + 5）；「转录组脱靶筛查」漏了引物页的全基因组选项；「装配对照」没写入口三处按实测改正；「装配对照」补「Liftover 页结果区」；另补「你会做什么」这类问法的能力识别

修复的核心：从「两套文案」改成「一页一条」

新增 llm/product_pages.py 作为功能页事实表，每个页面一条，写清入口、输入、输出、上限、口径， 以及「不在本页做什么」——最后一项是原来最容易糊的地方：别名页与位置查找页、基因查表型与表型查基因、 GO 富集与 KEGG 通路，两两之间原来会互相串。识别侧新增 detect_product_page()， 用页面别名正则（长名优先，避免「位置查序列」被「位置查找」抢走）定位页面， 再用用法问法正则判断是不是在问界面，两条同时成立才短路——这也是反向对照能保持 0 误伤的原因。

问：这个网站的界面怎么用？        → 认不出具体页面，回「功能地图」

六、遗留问题与建议

  • 菜单名与实际数据不一致（建议改导航，不是改文案）：Tools 里叫「KEGG 通路」，实际检索以 Reactome 为主。 答文已如实说明，但界面名称仍会先入为主。建议菜单改成「通路浏览器」。
  • 按基因取序列偏慢：实测 /api/tools/sequence?gene=tp53&types=cdna,promoter 单次 50.9s （启动子走 Ensembl REST，冷启动更慢），其余接口都在 5s 内。属于性能问题，不影响回答正确性。
  • News 没有独立页：点 News 落首页是产品既定设计（避免与首页重复），答文已照实说明；若希望有「更新日志」专页，需要新增页面。
  • 识别边界：「表达谱数据是 TPM 还是 FPKM」这类数据口径提问目前仍走科学车道。 要覆盖它，得把「口径」类问法也纳入用法识别，但会提高误伤风险，本轮未做。
  • 隐藏路由说明：#/id 与 #/upload 已从菜单移出但路由保留，答文已注明「菜单已移除、旧书签可用」， 避免用户按答文去菜单里找却找不到。
