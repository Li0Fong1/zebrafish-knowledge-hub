一、去重：口径与结果

1.1 为什么不能按「同 ID 就合并」直接删

先按三种判据各算一遍，结果差了两个数量级，说明"同 ID"本身不是同一基因的充分证据：

判据重复组涉及行合并后
同一 Ensembl ID（gene_basic.ensembl_id）71432,557
同一 NCBI GeneID（= GRCz12tu 基因 ID）46094532,082
同一 GRCz12tu 映射目标（含 synteny 投影）2,4425,76229,244

抽查发现后两类混进了明显的"不同基因被同一个 ID 串起来"：

  • actb1 与 actb2、shha 与 calcr、fgf8a 与 akap12b、mapk1 与 esrp1 共享同一 NCBI GeneID；
  • pcdh2g17/g9/g12/g28… 九个原钙黏蛋白基因、ugt1a1/a2/a4/a5/a6/a7 七个 UGT 基因被 synteny 投影到同一 GRCz12tu 位点；
  • 根因：gene_xref 的 Ensembl/NCBI 映射有错挂（actb2 被挂了 actb1 的 ENSDARG，sox9b 被挂了 anks1ab 的），而 gene_id_map_grcz12tu 的 synteny/blast 是"投影到最近的代表基因"，不是"同一基因"。
因此本次采用的判据：先按 NCBI GeneID（即 GRCz12tu 基因 ID）分组，再在组内判断 ——组内只有一个正式符号（其余是 ensdarg…／ZDB-GENE-…／si:…／LOC… 占位名）→ 合并到正式符号； 组内全是占位名 → 合并到字段最全的一条；组内有两个以上正式符号，只有互为命名变体（vegfa/vegfaa、 hsp70/hsp70.1、cox2/mt-co2 这类）才合并，其余判为冲突、一律不动。

2.2 liftover 结果可交叉验证

用 tp53 做闭环核对：把它在 GRCz11 的注释区间换算过去，落点与 RefSeq 直接给出的 GRCz12tu 坐标逐碱基一致——

GRCz11  5:24086227-24097805   （Ensembl r116 注释）
        ↓  danRer11ToGCF_049306965.2.over.chain.gz
GRCz12tu 5:24742747-24754325  ← 与 gene_assembly_xref 里 RefSeq 原生坐标完全相同

反向链同样精确回投（GRCz12tu 5:24742747-24754325 → GRCz11 5:24086227-24097805），说明两条链都是真的、没有近似填充。

三、liftover 工具：默认版本改为 GRCz12tu

页面原来刻意"不设默认"，两个下拉都是"请选择"。现在进页即摆好 GRCz11 → GRCz12tu （注释坐标出自 Ensembl 116 的 GRCz11，而平台统一按 GRCz12tu 呈现与取序列），用户仍可改成任意版本。

实测：首次请求 62 秒（建链索引），之后 0.2 秒；GRCz11→GRCz12tu 与 GRCz12tu→GRCz11 均返回 liftover_ok。

六、遗留与建议

  • 57 组冲突待人工确认：清单在 1.4，尤其是 her/hes、ntla/tbxta、lrh1/nr5a2 这几对——确认是同一基因后可以再合并一次。
  • gene_xref 的错挂没有根治：actb2 挂着 actb1 的 ENSDARG、sox9b 挂着 anks1ab 的，这类污染还会影响 ID 互转。彻底修需要拉 NCBI / Ensembl 官方 ID 对照重建，本次未做。
  • 160 个基因仍无 GRCz12tu 坐标：链文件在这些区间没有覆盖，界面上按 unplaced 显示，不会给假坐标。
  • 40 条区间长度漂移 >20%：已标 liftover_danRer11_review，建议抽检后再决定是否采用。
  • 8,000 余个基因没有 GRCz12tu 坐标（32,139 − 23,950）：其中多数是无染色体位置的条目，需要先补 GRCz11 坐标才能继续换算。
