## 三、最终整理方案

### 阶段 0（本次立即执行，全部可逆，风险最低）

**0.1 归档残留备份表**

```sql
RENAME TABLE zebrafish_db.gene_basic_bak_uniprot20261104
          TO zebrafish_archive.gene_basic_bak_uniprot20261104;
```

**0.2 重跑一致性巡检，刷新 `db_integrity_check`**

`scripts/upgrade_db_20261104.py`（不带 `--apply`）会把 12 项检查的当前真实值写回
`db_integrity_check`，其中第 12 项（bundle 缺口）会从旧值 6243 刷新为 0。

**0.3 清理别名表三类残留**（带备份 + 回滚列）

| 动作 | 对象 | 条数 |
|---|---|---|
| 删除 | 垃圾串（`-` / 空白 / 长度<2 且无字母数字） | 1,756 |
| 删除 | 自指（别名 = 本基因 `gene_name` 或 `gene_symbol`） | 22,600 |
| 标记 | 歧义串（挂 ≥2 基因）→ 不改数据，写 `gene_name_conflict` | 3,424 串 |

> 歧义串不删（删了会丢"按旧名检索"的入口），改显式进冲突表，检索时明示
> "需人工确认"。自指删除是安全的——检索命中 `gene_name` 走的是主表，不依赖自指别名。

### 阶段 1（单一事实源，建表双跑对账，不动线上）

**1.1 新建 `gene_name_index`（唯一事实源）**

```sql
CREATE TABLE gene_name_index (
  id          INT AUTO_INCREMENT PRIMARY KEY,
  gene_id     INT NOT NULL,
  name        VARCHAR(200) NOT NULL,
  name_norm   VARCHAR(200) NOT NULL,
  kind        VARCHAR(16)  NOT NULL,   -- symbol | synonym | former | full_name | xref
  source      VARCHAR(24)  NOT NULL,   -- zfin | ncbi | refseq | ensembl | uniprot | local
  rank        TINYINT      NOT NULL DEFAULT 50,
  is_current  TINYINT(1)   NOT NULL DEFAULT 1,
  created_at  DATETIME DEFAULT CURRENT_TIMESTAMP,
  UNIQUE KEY uk_name_gene_src (name_norm, gene_id, source),
  KEY idx_name (name_norm),
  KEY idx_gene (gene_id)
) DEFAULT CHARSET=utf8mb4;
```

写入来源：ZFIN `markers.txt`（官方符号）+ `aliases.txt`（别名）为权威，
`gene_alias` 中 `source='ncbi'/'refseq'` 的补充，`gene_basic.gene_name` 的本地符号。
**不写入**：自指、垃圾串、`name_kind != 'symbol'` 的编号代名（它们不是名称，是 ID）。

**1.2 新建 `gene_name_conflict`（歧义显式化）**

```sql
CREATE TABLE gene_name_conflict (
  id          INT AUTO_INCREMENT PRIMARY KEY,
  name_norm   VARCHAR(200) NOT NULL UNIQUE,
  name        VARCHAR(200) NOT NULL,
  gene_ids    VARCHAR(400) NOT NULL,
  n_genes     INT NOT NULL,
  reason      VARCHAR(200),
  status      VARCHAR(16) DEFAULT 'open',
  resolved_to INT NULL,
  created_at  DATETIME DEFAULT CURRENT_TIMESTAMP
) DEFAULT CHARSET=utf8mb4;
```

**验收（全绿才进阶段 2）**：索引表名称集合 ⊇ `gene_alias` 去垃圾去自指后的集合；
`GROUP BY name_norm HAVING COUNT(DISTINCT gene_id)>1` 的结果与冲突表 open 条数一致。

### 阶段 2（检索切换，并行比对）

`gene_match.search_classified` 改查 `gene_name_index`，与旧逻辑并行跑 200 个真实
query，逐条比对 gene_id 集合。不一致即切回（开关控制）。

### 阶段 3（收尾）

- 废弃 `gene_name_bundle`（观察一周无引用后 `RENAME` 归档）
- `gene_basic.interpro_domain` 加 `-- DEPRECATED` 注释，不删列
- 坐标表定主从（`grcz12tu_gene` 为主，其余标注派生）
- 旧库适配层切到主库后，`zebrafish_gene_v2_20260922` 归档

### 阶段 4（防回退，关键）

**4.1 导入脚本补 `name_kind` 判定**

在 `gene_collector.py` / `gene_bulk_collector.py` 的 INSERT 里，按与迁移脚本相同的
前缀规则写入 `name_kind`。这是当前唯一的"基因数会悄悄虚高"入口，必须堵上。

**4.2 巡检挂定时任务**

`upgrade_db_20261104.py`（只读模式）挂每周日，与 ZFIN 官方对账，异常自动告警。

## 四、执行顺序总览（万无一失的要点）

| 步骤 | 动作 | 可逆性 | 门禁 |
|---|---|---|---|
| 0.1 | 归档 1 张备份表 | RENAME 可逆 | 无 |
| 0.2 | 重跑巡检 | 只读 | 无 |
| 0.3 | 清垃圾串 + 自指 | 备份 + 回滚列 | 删除前整表备份 |
| 1.1/1.2 | 建索引表 + 冲突表 | 新表可 DROP | 无（不动线上） |
| 2 | 检索切换 | 开关切回 | 200 query 比对一致 |
| 3 | 废弃 bundle / 归档 | RENAME 可逆 | 观察一周 |
| 4.1 | 导入脚本补 name_kind | 代码回滚 | 语法检查 + 单条插入测试 |
| 4.2 | 巡检定时 | 删任务即停 | 无 |

**核心安全原则**：每个破坏性步骤都有「备份 → 执行 → 回滚路径」三步；检索路径的
切换用开关控制，任何一步比对不一致都能一键回到旧逻辑；数据层（阶段 0）与代码层
（阶段 4.1）解耦，互不阻塞。
