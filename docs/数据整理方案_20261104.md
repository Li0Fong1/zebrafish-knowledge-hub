### 主体结构（谁是谁的上游）

```
NCBI RefSeq GCF_049306965.2 (GRCz12tu)
        └── grcz12tu_gene            53,513  全量位点，权威坐标源
                └── gene_master_grcz12tu 53,359  去重后的 GRCz12tu 主档
```

## 二、发现的问题

### P0 — UniProt 数据错挂（已修复）

体检时 `gene_basic.uniprot_id` 有 21,161 个非空值，逐个与 UniProt 对照后：

| 问题 | 数量 | 典型 |
|---|---|---|
| 基因名与 UniProt 记录不符 | 491 | `shha` 挂着 `Q92050`（实为 `wnt5b`） |
| accession 在斑马鱼库里不存在 | 164 | `hsp70l`→`Q6P0X1` 是小鼠、`bmp4`→`O57343` 是非洲爪蟾、`fgf8a`→`O93480` 是鸡 |
| 一个 accession 挂多个基因 | 21 组 | `Q6PI52` 同时挂 6 个 calm 基因；`shha`/`wnt5b` 共用 |
| `gene_basic` 与 `gene_xref` 不同步 | 306 + 431 | 两处各有一批对方没有的 |

根因：历史回填按行/按名称批量写入，未校验「物种」与「基因名是否属该条目」，
局部批次还发生了行错位——`ntla` 拿到 `myod1` 的编号，`myod1` 拿到 `pou3f1` 的，`shha` 拿到 `wnt5b` 的。

### P1 — 结构与口径

1. **6 张一次性备份表滞留主库**，合计 34 万行、约 36 MB，均无主键：
   `gene_alias_bak_dedup20261103`(143,725)、`name_hit_unique_bak_dedup20261103`(135,969)、
   `gene_basic_bak_dedup20261103`(32,634)、`gene_assembly_xref_bak_dedup20261103`(29,844)、
   `gene_basic_uniprot_bak_20261031`(32,835)、`_dedup_map_dedup20261103`(425)。
2. **坐标四表并存**：`grcz12tu_gene`(53,513) / `gene_master_grcz12tu`(53,359) /
   `gene_region_annotation`(99,244) / `gene_assembly_xref`(30,815)，缺少主从声明。
3. **别名四表并存**：`gene_alias` / `symbol_alias` / `name_hit_unique` / `gene_alias_doc`，
   前两者字段重叠（`gene_alias` 的 `symbol` 类型 15,023 条与 `symbol_alias` 重复）。
4. **废字段**：`gene_basic.interpro_domain` 仅 30 条非空（0.1%），实际不可用。
5. **遗留视图** `gene`，仅 `database/mysql_client.py` 的连通性自检引用。

### P2 — 待人工裁决

- 57 组「同 ID 不同名」冲突（`her6/hes1`、`ntla/tbxta`、`lrh1/nr5a2`、`fxr/nr1h4`、`ackr3b/cxcr7` 等），
  合并前 `ntla` 这类旧名会拿不到蛋白编号（已确认：`ntla` 现为 NULL，其蛋白归 `tbxta`）。
- `gene_reference` 153,429 行 vs `literature_paper` 32,943 行，引用关系需说明口径。

## 三、已执行的整改

### 3.1 建立 UniProt 蛋白级注释层

**数据源**：UniProt REST `organism_id:7955` 全量导出（2026-11-04 快照）
`data/uniprot/uniprot_7955_all.tsv.gz`，78,189 条，其中 Swiss-Prot reviewed 3,385 条。

**新表 `uniprot_protein`**（脚本 `scripts/import_uniprot_protein.py`）：

| 列 | 说明 |
|---|---|
| accession (PK) / entry_name | 主编号与条目名 |
| protein_name / gene_names / gene_primary | 蛋白名与基因名（用于交叉校验） |
| length / mass | 长度、分子量 |
| reviewed | 1 = Swiss-Prot 人工审阅 |
| function_cc / subcell_cc | 功能描述、亚细胞定位 |
| keywords / go_ids | 关键词、GO |
| refseq_prot / ensembl_ids | 交叉引用 |

### 3.2 重建 accession 映射

**脚本**：`scripts/rebuild_uniprot_map.py` → `scripts/apply_uniprot_map.py`

匹配规则（三级 + 全局唯一分配）：

1. 基因名 == UniProt `gene_primary`（name_primary）
2. 基因名 ∈ UniProt `gene_names`（name_synonym）
3. 本地别名表 → UniProt 名称（alias）
4. **同一 accession 只允许分配给一个基因**，reviewed 优先，其次最短 accession
5. 现值若本身在候选集合内则保留（最小变更，避免同蛋白换号）

结果（32,139 条全覆盖）：

| 动作 | 数量 | 含义 |
|---|---|---|
| keep | 20,782 | 原值正确，保留 |
| fix | 346 | 错挂，换正确编号 |
| fill | 1,242 | 原本空白，新补 |
| clear | 33 | 跨物种/被他人占用，清空 |
| conflict | 74 | 多候选且已被占用，保持空白待审 |
| none | 9,662 | 无任何匹配（主要为克隆/EST 名） |

**整改前后**：

| 指标 | 前 | 后 |
|---|---|---|
| 有 accession | 21,161 | **22,370** |
| 唯一 accession | 21,128 | **22,370**（一一对应） |
| 跨物种/不存在 | 164 | **0** |
| 一号多基因 | 21 组 | **0** |
| `gene_basic` 与 `gene_xref` 不一致 | 737 | **0** |

**安全措施**：整表备份 `gene_basic_bak_uniprot20261104`（32,139 行）；
新增 `uniprot_id_old` 列保存原值（379 条有值，已校验与备份 100% 一致），可逐条回滚。

### 3.3 接入 API

`database/gene_toolkit.py::get_gene_detail()` 新增 `uniprot` 块，
`/api/gene/{name}` 直接返回蛋白名、长度、分子量、功能描述、亚细胞定位、reviewed 状态。

实测 `GET /api/gene/shha`：

```

```

### 3.4 口径同步

`web/js/about.js`、`web/js/guide.js`、`web/js/app.js` 的「有蛋白编号」全部由 21,161 改为 22,370，
并注明其中 2,779 条经 Swiss-Prot 审阅。`web/index.html` 资源版本升至 `20261104d`。

## 五、复现命令

```bash
# 1. 体检
python scripts/import_uniprot_protein.py          # 建表并灌入 UniProt
python scripts/rebuild_uniprot_map.py --report    # 只看预演，不写库
python scripts/rebuild_uniprot_map.py             # 写入 gene_uniprot_map
python scripts/apply_uniprot_map.py --dry-run     # 应用前确认
python scripts/apply_uniprot_map.py --apply       # 备份 + 应用 + 校验

# 2. 回滚（单基因）
UPDATE gene_basic SET uniprot_id = uniprot_id_old
 WHERE gene_name = 'shha' AND uniprot_id_old IS NOT NULL;

# 3. 回滚（全量）
UPDATE gene_basic b JOIN gene_basic_bak_uniprot20261104 k ON k.gene_id = b.gene_id
   SET b.uniprot_id = k.uniprot_id;
```

## 六、后续规范

1. **任何跨库 ID 回填必须校验物种**：`uniprot_protein` 建表时只收 `organism_id:7955`，
   外部导入前先 `EXISTS` 检查 accession 是否在本表内，杜绝再引入小鼠/爪蟾条目。
2. **禁止一号多基因**：`uniprot_id` 在 `gene_basic` 上应保持唯一，
   加唯一索引前需先跑一次 `GROUP BY uniprot_id HAVING COUNT(*)>1`。
3. **别名只维护一份**：新别名一律写 `gene_alias`，`symbol_alias` / `name_hit_unique` 视为派生缓存，
   可由 `gene_alias` 重建。
4. **备份表命名**：`<表名>_bak_<日期>`，建立后 30 天内归档，不留在主库参与 `SHOW TABLES` 干扰盘点。
