## 二、新增内容

### 2.1 表 `grcz12tu_gene`（`sql/grcz12tu_full_migration.sql`）

独立于 `gene_basic`，不受 `gene_assembly_xref` 的外键（gene_id → gene_basic）限制，承载 RefSeq 注释的全量基因。字段：GeneID、符号、locus_tag、biotype、染色体、genomic accession、起止、链、assembly_unit、seq_type、代表转录本、`gene_id`（能映射到本地主表时回填，**故意不加外键**）、source。

### 2.2 脚本 `scripts/import_grcz12tu_full.py`

- 下载/缓存 `.2` 的 feature_table，解析全部 gene 行（Primary Assembly，排除 alt/patch/fix）
- 建表 → 写全量 → 回填 `gene_id`（来自 `gene_assembly_xref` 与 `gene_xref(ncbi_gene)`）
- 同步版本：`assembly_registry` 改 `.2`；`gene_assembly_xref.source` 改写
- 自校验并打印抽样；`--dry-run` 只解析不写库
- 幂等：重复执行按「GeneID+染色体+起点」更新，不会重复插入

执行方式（服务器）：

  /data/zoujin/deng/miniconda3/envs/zebrafish/bin/python scripts/import_grcz12tu_full.py

## 五、过程中的两个事故与处置（留痕）

1. **MySQL 卡死**：服务器 IO 一度掉到 6.5 MB/s，mysqld 多个线程处于 D 状态，握手超时、SIGTERM 3 分钟无响应。经你授权后 `kill -9` 并原参数重启，InnoDB 崩溃恢复完成，`gene_basic` 32,564 行完好，未丢数据。
2. **误用本机旧版覆盖服务器源码**：`database/coord_liftover.py` 本机是 10-28 的旧版（19 KB，无 `list_supported_pairs`），上传后导致 liftover 接口 500。已从 `logs/_bak_hang2_20261029T052154Z/coord_liftover.py`（10-29 11:21，32,638 字节）恢复。其余 8 个文件经导入符号校验与函数集合比对，确认**相对服务器 10-28 版本无任何功能删减**，予以保留。

> 教训：服务器不是 git 仓库，本机与服务器存在版本漂移。今后改动服务器代码前应先按文件比对，而不是整文件覆盖。
